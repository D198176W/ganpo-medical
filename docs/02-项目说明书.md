## 2. 系统架构

### 2.1 现状（4 个独立服务，无网关）

```
前端 Vue3 SPA (:5173)
   ├── 硬编码 → consult          :8080    AI 问诊
   ├── 相对路径 /api/* → pathology :8082   病理（无 proxy 配置，dev 下 404）
   └── 相对路径 /api/* → medical-resource :8083（调用方式有 Bug）
   ※ health-management :8081 前端完全未对接

4 个模块各自持有：独立 MySQL 库、各自的 User 表、各自的 JWT 实现、各自的响应体
```

### 2.2 目标架构（微服务化）

```
浏览器 → Nginx(:80) → ganpo-gateway(:8080) → 各业务服务
                          ↑ Nacos 服务发现
   ganpo-common / ganpo-common-web / ganpo-api  ← 公共层
```

| 模块 | 端口 | 职责 |
|---|---|---|
| `ganpo-common` | — | 统一响应体、分页、错误码、异常、JWT 工具、用户上下文（**零 Web 依赖**） |
| `ganpo-common-web` | — | 全局异常处理、用户上下文拦截器（Servlet 专用） |
| `ganpo-api` | — | 跨服务 DTO + OpenFeign 客户端 |
| `ganpo-gateway` | 8080 | 路由、统一鉴权、CORS、Sentinel 限流 |
| `ganpo-auth` | 8081 | 认证中心（收编 3 套重复用户体系） |
| `ganpo-health` | 8082 | 健康管理 |
| `ganpo-consult` | 8083 | AI 问诊 |
| `ganpo-pathology` | 8084 | 病理服务 |
| `ganpo-resource` | 8085 | 医疗资源 + 预约挂号 |
| `ganpo-notify` | 8086 | 通知中心（WebSocket + RocketMQ） |

> 🔴 `ganpo-common` **不得引入 `spring-boot-starter-web`**：Spring Cloud Gateway 是 WebFlux 响应式，servlet 依赖会导致网关启动失败。

**版本矩阵**：Spring Boot **3.2.4** + Spring Cloud **2023.0.1** + Spring Cloud Alibaba **2023.0.1.0** + Nacos **2.3.2**
（依据：[SCA 官方版本表](https://sca.aliyun.com/docs/2023/overview/version-explain/)）

### 3.1 `consult` — AI 智能问诊（:8080）

### 3.2 `health-management` — 健康管理（:8081，context-path `/health`）

### 3.3 `pathology` — 病理服务（:8082）

## 4. 环境搭建

### 4.1 数据库（项目专属实例 :3307）

> 项目使用**独立实例 `:3307`**，由 `scripts/start-ganpo-mysql.ps1` 启动。

复用本机已有的 MySQL 9.5.0 二进制，创建一个隔离实例：

```powershell
$BIN = 'D:\CodeTool\mysql-9.5.0-winx64\mysql-9.5.0-winx64\bin'
$DATA = 'D:\CodeTool\mysql-ganpo-data'

# 1) 初始化独立数据目录（只需一次）
& "$BIN\mysqld.exe" --initialize-insecure --datadir=$DATA

# 2) 以 3307 端口启动（封装为 scripts\start-ganpo-mysql.ps1）
& "$BIN\mysqld.exe" --datadir=$DATA --port=3307 --console

# 3) 首次设置 root 口令并建库（按需）
& "$BIN\mysql.exe" -h 127.0.0.1 -P 3307 -u root -e "ALTER USER 'root'@'localhost' IDENTIFIED BY '你的口令';"
```

需要创建的 4 个库：

```
guiguxiaozhi        # consult
health_management   # health-management（⚠️ 无脚本，需手写）
pathology           # pathology（✅ 有脚本）
medical_resource    # medical-resource（✅ 有脚本，注意库名要改成 medical_resource）
```

## 6. 接口约定

### 6.1 统一响应体（目标）

```json
{ "code": 0, "message": "成功", "data": { } }
```

- **成功码 = 0**（前端 `utils/request.js` 已按 `code === 0` 判定）
- 当前 4 个模块有 3 套格式（见 `AGENTS.md` §8），Phase 3–4 统一

### 6.2 鉴权链路（目标）

```
登录 → ganpo-auth 签发 JWT
请求 → Nginx → Gateway 校验 JWT → 注入 X-User-Id / X-User-Roles → 下游服务
下游 → UserContextInterceptor 读取请求头 → UserContext(ThreadLocal)
```

- 下游服务**不再各自解析 token**
- JWT **必须**包含 `authorities` 声明（否则 `health-management` 过滤器会 NPE——已在 Phase 1 加兜底，但仍建议写入）

## 9. 常见问题（FAQ）

**Q1：`mvn` 报 `Non-resolvable import POM: spring-boot-dependencies:3.2.4 absent`？**
A：本机 Maven 的 `settings.xml` 把本地仓库指到了几乎为空的 `mvn_repo`。加参数 `-Dmaven.repo.local=$env:USERPROFILE\.m2\repository`，或修改 `settings.xml` 的 `localRepository`。

**Q2：报 `version can neither be null, empty nor blank`？**
A：这是 `maven-compiler-plugin` 的 `annotationProcessorPaths` 里 lombok 缺少版本号导致的历史问题。**已修复**（移到父工程 `pluginManagement`）。若在子模块新增 compiler 插件配置，请勿重复声明 `annotationProcessorPaths`。

**Q3：服务起不来，报找不到数据库？**
A：4 个库本机还不存在，需先完成 Phase 2 建库。连接端口为 **3307**。

**Q4：`SeparateChatAssistant` 为什么被注释了？**
A：它依赖的 `chatMemoryProvider` Bean 在 `SeparateChatAssistantConfig` 中被注释，且 `my-prompt-template*.txt` 资源文件不存在，保留会导致 Spring 启动失败。

**Q5：为什么 `package.json` 里有 `tailwindcss` 但样式不起作用？**
A：`tailwindcss 4.1.14` 是**未使用的死依赖**（无 `tailwind.config.js`、无 `postcss.config.js`、无 `@tailwindcss/postcss`）。原本带 Tailwind 指令的 `src/styles/global.css` 是**孤儿文件**（无人引用），已在本次梳理中删除。但 3 个紧急救助组件的 `<style>` 里仍有 `@apply` 未生效，导致按钮/卡片样式缺失——这是**待修的视觉 Bug**。

**Q6：我想改前端样式，`global.css` 在哪？**
A：`src/assets/styles/global.css`（`main.js` 引入，纯 CSS）+ `src/assets/styles/loading.css`（`index.html` 引入，加载动画）。
